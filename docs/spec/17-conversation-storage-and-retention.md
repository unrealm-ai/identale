# 存储、保留与恢复

## 数据归属

新本地安装的平台默认使用 `~/.identale/platform/platform.sqlite` 保存平台配置与相应元数据。运行服务默认使用 `~/.identale/runtime/runtime.sqlite` 保存会话索引、Task / Run、输入、事件与投递等运行事实。两个数据库不能互换，也不能用同一文件启动两个角色。本地默认路径不受旧 `.dentity` 目录影响；显式路径配置优先，服务器数据位置以其受保护的部署配置为准。

内置 Runtime 的正文保存在运行库旁的 `builtin-records` JSONL 目录，SQL 保存可信记录引用与状态。新本地 PI Host 默认状态根为 `~/.identale/runtime-host-pi`，在状态、Session 与执行资源目录中保存原生记录、文件和产物。Skill 原件默认位于 `~/.identale/resources/skills`，由 `DENTITY_SKILL_RESOURCE_ROOT` 覆盖。本地不再探测旧 PI 状态或 `~/.identity/resources/skills`，使用自定义资源位置需显式配置。

## 保留与摘要

会话压缩摘要不等于删除原文。内置实现使用当前记录、摘要与归档文件，维护任务的状态和发布结果需要可靠记录。保留策略、近期原文尾部与触发设置以运行服务配置和 `packages/runtime-builtin` 的实际实现为准，不能推断所有外部 Runtime 已支持同一策略。

消息、模型响应、工具参数、附件和产物都可能包含私人信息。记录文件和目录需要访问控制，向外分享前脱敏；`.gitignore` 只防误提交，不提供访问控制或加密。

## 备份

在服务停止或另有明确一致性方案的条件下，保留相互对应的平台与运行数据库、所需 SQLite sidecar、完整 builtin 记录、PI Host 状态 / Session / 执行产物、Skill 原件以及原私有凭据。只复制 SQLite 不能恢复全部会话、文件或工具资源。

主密钥与服务凭据应在仓库外独立保护。丢失模型主密钥可能无法解密原模型 / 渠道凭据，不能通过生成新密钥修复原密文。

## 恢复与迁移

本地启动器首次生成 `.env` 时写入显式配置或 `~/.identale` 默认路径，之后按进程环境变量 → `.env` → 程序默认值解析配置。数据库、私有凭据、启动器、托管 Node 与资源目录均不再自动回退到旧位置，新旧凭据同时存在也只读取选中的路径。选中的平台库或运行库已存在但缺少原密钥时，拒绝自动生成替代密钥；未被配置选中的旧库不参与初始化检查。复用已有安装须明确配置完整匹配的数据、资源与原密钥。启动器不会移动或删除这些文件，切换前须先停止旧启动器实例。

记录根绑定数据库身份与解析后的数据库路径。恢复应保持相互匹配的数据库、记录、配置、原路径和权限；跨路径恢复或数据库身份改变需要具体迁移方案。不要手工拼接不同时间点的文件后宣称恢复成功。

代码对部分旧结构明确拒绝启动，不自动清库、迁移旧正文或替换缺失密钥。`scripts/maintenance/split-storage-migrate.mjs` 和 `scripts/maintenance/reset-builtin-test-context.mjs` 属于有副作用的离线维护工具，不参与正常安装或启动。前者要求明确源库、目标目录和离线确认；后者默认仅检查，实际归档需要明确离线确认和新的私有备份目录。运行前需单独确认数据范围、备份和验证方式。
