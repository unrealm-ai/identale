# 数字员工、角色与配置

## 产品对象

数字员工承载长期身份、职责与使用边界。用户在工作区创建员工，配置模型、使用范围、渠道和业务资源；一次请求不需要再创建一个员工。群、模型或技术工具不同，也不必机械拆成不同员工；需要独立职责、权限或业务所有权时再拆分。

一个员工有交互与执行两类角色。交互负责持续交流、任务管理和获准的只读业务查询；执行负责需要 Skill、MCP 和本地工具的后台工作。当前交互主线为 builtin，执行为独立 local-pi，不能因为契约定义了多种角色就假设任意 Runtime 已实现全部能力。

## 配置到执行

1. 在工作区配置有效模型及员工使用范围。
2. 注册 Skill / MCP 等资源，并通过能力包选择可用资源和调用范围。
3. 配置渠道应用、使用人规则和必要业务触发绑定。应用认证、渠道在线、使用授权和模型可调用分别核对。
4. 运行侧同步配置；为 Task 固定所需版本和授权范围，准备执行配置后再派发。

能力包可以继承或收窄员工整体使用范围，不因资源被登记就向所有任务开放。平台账号与渠道原生身份是不同概念，渠道使用者不必全部注册成平台账号；模型不能自行填写可信身份。

[ResolvedAgentSpec](../../packages/contracts/src/runtime-provisioning.ts)包含角色、配置来源版本、模型引用、Skill 版本 / digest、MCP 工具范围、平台工具及必要 Runtime 能力等。它是执行准备契约，不是要求用户手写的配置文件，也不证明其中每种资源或 CLI 适配已可用。

## 生命周期边界

“已保存”是平台配置事实，“已同步 / 已准备”是运行服务和 Host 的事实。准备失败应显示缺项或不支持，不静默换模型、扩大工具或跳过必要能力。执行准备的缓存命中不是某个 Task 的授权。

已接纳 Task 和等待人工任务使用固定快照，不能偷偷跟随最新全局配置扩大权限。撤权、员工停用、现有任务取消与配置同步存在独立时序；本项目不承诺保存配置即刻终止所有在途工具。

包和员工使用范围是业务准入，不能代替操作系统权限。CLI / Bash、文件、模型端点和外部 MCP 的真实权限需部署与业务系统共同约束。当前没有 OS 沙箱，见[安全说明](../../SECURITY.md)。
