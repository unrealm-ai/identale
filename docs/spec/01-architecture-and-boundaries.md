# 架构与模块边界

## 从一次委派开始

用户在有权使用的 Web 或渠道会话中向数字员工提出请求。内置交互 Runtime 根据当前会话与获准工具处理请求；需要后台执行时，通过平台任务用例建立 Task，由运行服务下发到独立 PI Host。用户可以继续交流，任务进度、最终结果和通知分别记录。

Task 是业务工作，Run 是一次执行段或尝试，Delivery 是结果投递。任务完成不代表通知已经送达，通知失败也不应让业务任务重新执行。等待人工信息后继续同一 Task 时，可以创建新 Run，不应伪装成旧 Run 一直运行。

## 实际代码与进程

| 模块 | 当前代码位置 | 职责 |
| --- | --- | --- |
| 平台服务 | `apps/control-plane/src/main.ts`、`apps/control-plane/src/split` | 账号、工作区、员工、权限、目录、模型和资源配置 |
| 运行服务 | `apps/control-plane/src/runtime-main.ts` | 渠道交互、会话、任务调度、运行事实和结果投递 |
| 内置交互 Adapter | `packages/runtime-builtin` | 受限 LLM + tools 循环和私有会话状态，装配于运行服务 |
| PI Host | `apps/runtime-host-pi` | 独立进程、执行准备、worker、原生执行会话和过程事件 |
| Web | `apps/web` | 用户对话、管理配置和状态展示 |
| 领域 / 应用 / 契约 | `packages/domain`、`packages/application`、`packages/contracts` | 规则、用例、Port 与 DTO |

平台和运行服务使用独立数据库，运行侧通过配置接口获取所需配置，平台通过运行服务查询相关运行事实。PI Host 被动接收获准的执行配置和命令；按需工具通过受控接口读取授权材料，不直接把平台数据库交给模型。

受支持的本地启动与 host 部署入口按真实代码目录维护跨 HOME / UID 可识别的模式记录，在项目配置写入、依赖安装和构建前取得，保持到本地清理或部署结束。同用户本地重启沿用既有实例交接；跨模式冲突明确拒绝，异常退出的记录需原模式核验清理后才可切换。服务已运行时，本地入口在取得记录后再次检查 systemd 状态。本地 SIGHUP 与 SIGINT / SIGTERM 共用进程组停止清理。具体操作、手动命令不受此机制覆盖的范围和待验证环境见[部署说明](../deployment.md#同一代码目录的模式互斥)。

## 配置、命令与事实的方向

- 平台保存配置权威。运行侧主动同步版本化配置，不直接打开平台数据库；配置未就绪不能用空规则当作默认授权。
- 运行侧拥有渠道 / 交互 / Task / Run / 投递事实，在同一服务内共享运行存储。builtin 是其中的 Adapter，不要求另建一个常驻服务或业务数据库。
- 运行侧向 PI Host 下发准备配置、执行命令并消费执行事件；Host 保存执行观察、原生记录与产物。执行层不负责重新选择业务权限、模型或确认人。
- 获准的内置历史 / 事项工具可经可信 Host 调用运行侧窄业务 API。这是受控数据通路，不是把配置解析或调度责任倒置。
- 平台页面读取运行视图，不能成为第二个任务状态写者。服务存活、配置就绪、供应商连通和业务执行成功分别表示。

关键装配见[分服务入口](../../apps/control-plane/src/split/server.ts)、[配置同步](../../apps/control-plane/src/split/config-sync.ts)、[表归属](../../apps/control-plane/src/split/table-ownership.ts)与[任务 Runtime Adapter](../../apps/control-plane/src/task-runtime.ts)。

## 依赖方向

业务逻辑通过能力明确的 Port 依赖外部系统，由 Adapter 接入具体模型、渠道、SQLite 和 PI。现有 SQLite 事务及配置服务仍有实现约束，不能因存在 Port 就宣称已支持任意数据库或 Runtime。

交互控制负责触发、发言、打断和调度，不承载通用执行 Harness。内置循环只封装在内置 Adapter。业务 Skill / MCP 进入执行 Agent，不能通过提示词让交互工具越过权限边界。

## 扩展与非目标

新 Adapter 应兑现已有契约并明确实际能力，不用统一接口掩盖不支持的行为。新增业务规则优先放入领域 / 应用层；数据库、HTTP 和 SDK 细节留在适配或装配层。现有实现仍含未完全抽离的应用编排，不将目录分层描述成所有边界已经完美完成。

本项目不自研通用 Agent Harness，不以 Runtime 内部并行分析 subagent 创建平台业务 Task，也不为每个渠道拆一个微服务。业务委派、事项交接与 Runtime 内部工作应分别管理。

## 验证与未实现边界

源码与测试提供了本地状态机、API、PI SDK 和 worker 链路。渠道实际能力、模型协议、附件、人工确认与事项功能应按配置和对应实现验证。远程执行平台、通用沙箱、多机自动迁移和任意数据库替换不是默认能力。
