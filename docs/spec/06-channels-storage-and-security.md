# 渠道、权限与安全

## 配置与使用过程

管理员为员工配置工作区模型、员工使用范围、业务能力包和需要的渠道应用。连接身份校验、长连接在线、使用授权和模型就绪分别显示；配置保存或 SDK 认证成功不等于真人消息已收发。

普通 Web 用户先按工作区和员工使用权准入。渠道消息通过已认证的 Adapter 绑定来源、应用、租户和用户身份，不要求渠道用户全部注册平台账号。模型生成的参数、昵称或正文中的身份标签不是可信身份。

平台账号密码使用 Node 内置 Argon2id，存储格式为 `$argon2id$v=19$…`。现有版本写入的凭据可原样验证，包括 19 MiB / 2 次 / 1 并行度和历史默认的 64 MiB / 3 次 / 4 并行度。校验在派生前检查编码和参数边界，登录沿用原凭据记录。

## 权限边界

- 三渠道分别配置使用范围，新建默认空白名单并允许群成员在群内使用；群内许可不开放私聊，黑名单优先。能力包默认继承有效范围，只能进一步收窄。
- Skill 内容不授予权限；MCP 工具需按登记、发现结果和任务快照限制，不能靠提示词隐藏越权工具。
- 会话按渠道和上下文隔离；群、话题、私聊及任务关联不自动授予跨会话读取权。
- Task / Run 使用明确授权的上下文与资源版本。配置更新、旧任务继续、撤权传播和缓存有各自时序，不承诺保存配置的瞬间所有执行已经停止。
- 知道任务 ID、会话 ID 或资源引用不等于拥有读取权。业务知识、文件与结果应通过相应授权接口获取。

## 渠道差异

当前代码包含飞书 WebSocket、钉钉 Stream 和企业微信智能机器人相关 Adapter。各渠道的应用身份、目录身份、可见范围、历史、附件与发送能力不同；普通机器人在线不代表可读取所有群历史或会议材料。

企业微信仅使用智能机器人 BotID / Secret，用户身份按机器人来源隔离；全员模式不等于已验证企业员工或排除外部联系人，相关人员名单身份映射未知时安全阻断。飞书 open_id 具有应用作用域；钉钉应用身份不能冒充已验证企业用户。自动通知需固定获准接收目标，不能因通知失败重新执行 Task。

前端指南链接指向外部产品说明，菜单、权限和租户实际支持需要部署时核对。

具体能力表、回执和新 Adapter 接入流程见[渠道能力与扩展](26-channel-capabilities.md)。

## 执行边界

当前 local-pi 不提供文件系统 / 网络沙箱。原生 Bash 可按操作系统身份访问主机资源，不受业务包清单完整约束。内置身份校验、MCP 工具选择与进程分离不能替代 OS 隔离。

服务器模板使用专用 `identity:identity` 普通账号，并禁止提权及清空 capabilities；安装和系统配置仍需 root。本地启动使用当前用户。各服务、任务仍共享系统账号，降权不提供文件、进程和网络的租户隔离，不能据此承诺可承载不可信用户。

目录改权、原凭据保留、启动身份检查和失败恢复以[部署说明](../deployment.md)为准。生产环境使用前应在目标 Linux 主机独立验证安装、升级与权限隔离配置。

服务器代码可保留在用户 home 中，通过定向访问 ACL 向 `identity` 提供必要祖先目录的遍历及运行产物 / 依赖读取，不更换源码属主、不开放整个 home、不向 `/root` 授权。授权前持久化原 ACL，失败时按 inode 和当前 ACL 核对回退；后续外部改权或目录移动需重新检查。具名 ACL 与普通权限共同决定实际可见性，不能据此宣称整个 home 或同账号任务已隔离。实现与验收范围见[原目录部署](../deployment.md#在用户-home-中原目录部署)。

其他安全及报告方式见 [SECURITY.md](../../SECURITY.md)，数据保护见[存储与恢复](17-conversation-storage-and-retention.md)。
