# 读取已分享的会议资料与云文档

## 如何读取已分享的资料

在获准的群、话题或私聊中向数字员工明确分享资料并交办任务。Identale 默认使用该员工所连接的应用身份。运行服务核验消息来源和应用访问权，将获准的材料交给任务读取，结果返回原会话或话题。

应用需要同时满足所用 API 的权限和具体资料的访问权。以下是当前已适配的范围，真实租户联调状态见文末。

## 各渠道的范围

| 渠道 | 当前读取范围 | 主要前提与限制 |
| --- | --- | --- |
| 飞书 | 指定 Docx 正文、妙记已有摘要与逐字稿。会议卡片可按具体场次查找关联的妙记或笔记文档 | 摘要、逐字稿和笔记的访问权分别核验。统一纪要逐字稿暂未接入应用身份读取 |
| 钉钉 | 指定 `docKey` 的文档块、指定 `conferenceId` 的云录制逐字稿 | 使用企业内部应用。应用需要能通过通讯录核验原消息发送者，并访问具体资料 |
| 企业微信 | 当前未开放会议和云文档读取 | 应用身份、接口契约和资料访问权仍待核验 |

三家的图片、文件消息是另一条能力，见[渠道配置与能力](26-channel-capabilities.md)。本轮不提供资料搜索、创建或修改文档、平台原生待办与日程。

## 飞书如何准备与使用

1. 为现有应用开通需要的读取权限。Docx 使用 `docx:document:readonly`；妙记逐字稿使用 `minutes:minutes.transcript:export`，已有纪要使用 `minutes:minutes.artifacts:read`。会议卡片涉及的会议、录制和笔记接口另受各自权限约束，以官方控制台和实际接口结果为准。
2. 让应用具有这份资料的对象访问权。例如文档所有者或管理者可通过“添加文档应用”将应用加为可阅读协作者。妙记有独立对象权限，不能用文档协作者权限代替。
3. 在获准群或私聊明确分享资料并交办任务。支持飞书/Lark 官方域名下的 HTTPS `/docx/文档标识`、`/minutes/妙记标识`，可带 `?from=from_copylink`；其他查询参数或片段暂不识别。原生会议卡片还需准确的会议号码及起止时间，以定位实际场次。
4. 打开任务详情，查看正文、摘要或逐字稿的准备状态。

## 钉钉如何准备与使用

- 现有企业内部应用需要目录成员详情权限 `qyapi_get_member`，用于将可信消息发送者的 staffId 经官方目录响应核对为 unionId。系统不会根据名字或字符串相等猜测 DWS 用户、staffId 与 unionId 的关系。
- 文档读取需要 `Storage.File.Read`。操作用户必须处于允许范围并具有具体文档访问权，资源组织应与应用一致。
- 会议云录制逐字稿需要 `VideoConference.Conference.Read`，使用确切的 conferenceId；录制和文字必须已经生成。创建者、参与者及资源所属组织的实际权限仍需真实租户验收。
- 当前以明确引用接入：`dingtalk:document:DOC_KEY` 或 `dingtalk:meeting:CONFERENCE_ID`。占位标识需替换为真实资源标识。尚未实现分享 URL 到这些标识的自动解析，不能直接用会议号码替代。
- 文档保留官方返回的嵌套块结构。遇到未适配块、缺失子内容、未知表格结构或超出读取预算，会明确报告，不能把不完整正文当作完整材料。不会自动下载文档中的图片或跟读链接。
- 云录制提供逐字稿，不伪造官方摘要。需要总结时，执行层可以基于已获准逐字稿生成总结，并注明它是生成的总结。DWS AI 听记不是这条云录制接口，本版未默认接入。

## 状态怎么看

在「渠道连接」的「应用身份读取」中可以核对适配类型、所需 API 权限和限制。拥有员工管理权限的用户可在任务详情的当前运行中点击「查看任务材料」，按正文、摘要、逐字稿查看已保存的准备结果。

- **已预下载**。已有该次准备得到的材料，后续使用仍需检查权限。
- **资料生成或准备中**。例如资料生成中、接口限流或临时服务故障。
- **读取权限不足**。可能是来源已失效、缺少 API 权限或缺少具体资料访问权。上游未区分原因时，页面会说明仍需核验。
- **资料暂不可用或当前未支持**。例如资源不存在、未提供该内容类型或接口尚未适配。
- **读取失败**。例如网络读取失败或响应格式不符合接口契约。
- **尚无准备结果**。当前材料还没有可查看的准备记录。

「刷新材料准备状态」只查询已有记录。应用读取失败时，系统会保留失败原因供排查。部署中若启用了飞书个人 OAuth 原型，该原型独立显示，应用读取仍使用原应用身份。

## 原会话与任务材料范围

在群里明确分享的资料获准读取后，可以在原群回复，无需再次确认同群分享；私聊资料仅在原私聊回复。A 群的任务不会自动把资料或结论提供给 B 群。

同一群会话或同一话题内，其他有员工使用权限的成员可在新任务中明确选用已分享的资料。系统分别记录原分享者和当前调用者，钉钉仍按原分享者核验业务接口所需的身份。这项复用规则限于可信的同群、同话题来源。

同一资料可以在 B 群再次明确分享。系统会重新检查 B 群的消息来源和应用资源权限，并为新任务单独授权。

## 事项交接时怎样选择材料

交接数字员工会根据接收者的目标自主选择必要材料，不要求用户每次逐项勾选。它应先查看获准内容，只带完成下一步所需的说明、已发布产物或原始素材；摘要足够时优先选择摘要。读过一份资料，不代表交接时自动带上它。

运行服务会核验所选材料的来源、版本、权限和接收任务。接收员工得到的是本次交接的目标、验收要求、交接说明及选中材料，不会因此获得前任的全部事项历史、其他资料或应用凭据。原始素材与已发布产物分开选择；仅选择摘要时，接收者不能顺带读取原文或逐字稿。

即使只交接摘要说明、不附文件，相关资料的来源权限也会继续检查。资料撤权、版本变化或来源绑定失效时，后续读取和任务准备会被阻止，并报告原因。再次交接仍需重新选择和核验，不会扩大原有范围。

## 权限变化与验证边界

准备材料、继续任务和输出结果前会复核来源、调用身份、资源版本与目标。撤权会影响后续读取和输出。执行环境中已经发放的材料字节无法立即收回，仍需按部署的数据保留与清理规则处理；工作目录与进程分离不是操作系统安全沙箱。

本地隔离合成测试覆盖应用身份与凭据修订、显式来源、固定目标、资源拒绝、版本变化、派生材料、分页、部分失败，以及明确选择素材后的事项交接、多次交接和撤权阻断。真实应用的 scope、对象 ACL、会议就绪状态、返回内容及权限变更仍需逐项端到端验收。
