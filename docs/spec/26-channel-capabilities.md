# 渠道配置与能力

## 在员工设置中查看渠道能力

在数字员工的「渠道连接」页添加或编辑渠道。保存后分别核对凭据验证、连接状态和员工使用范围，再用获准账号测试消息收发。展开「连接诊断」可查看机器人身份和测试入站结果；目录、群历史和业务资料的权限需分别核验。 渠道页可见时，三渠道长连接状态会持续自动刷新，包括已连接后的断线和恢复；离开页面或隐藏窗口时暂停，返回后重新读取。状态刷新不会覆盖尚未保存的表单，查询失败显示状态暂不可用，不等同于机器人离线。

- 私聊、群 @、企微定向消息、普通群消息、关键词和近期群上下文分别显示。缺少权限时，先在厂商应用后台补齐权限，再重新验证渠道。标为不支持的能力不会显示对应配置项，未声明的可选能力显示为未知。
- 图片与文件分别列出私聊和群聊的接收、发送能力。实际收发还受消息目标、文件类型、大小和发送权限限制。
- 「应用身份读取」列出已适配的资料类型和所需的 API 权限。实际读取时还要核验具体资料的访问权。查看任务材料准备状态和分渠道配置，见[读取会议资料与云文档](27-business-resource-reads.md)。

## 当前企业机器人路线

下表反映代码分支和限制，不是对真实租户的联调结论。

| 渠道 | 入站 / 会话能力 | 历史与话题 | 出站 |
| --- | --- | --- | --- |
| 飞书 | WebSocket 接入；私聊、@ 与普通消息取决于应用和授权 | 有群 / 话题分页实现；话题降序明确不支持，时间过滤与覆盖范围需按结果处理 | 文本、回复以及原生图片 / 文件实现；实际权限与文件限制需验证 |
| 钉钉 | Stream 接入；私聊和群 @；图片、富文本图片及私聊文件已接入；当前机器人入口不接群文件 | 当前企业机器人 Adapter 不支持历史 / 话题 / 普通消息读取 | 文本及原生图片 / 文件发送实现；文件格式受机器人 API 限制；不支持回复指定消息 |
| 企业微信 | 智能机器人接收私聊及群定向消息；受支持的图片、文件、混合、语音转写与引用结构已接入，不伪造 @ | 当前 Adapter 不支持会话查询、历史或话题 | 复用唯一接收连接发送 / 回复文本和原生图片 / 文件；上传与最终发送分阶段授权 |

飞书 `open_id` 具有应用作用域，不能跨应用当作同一个全局用户 ID。企微仅使用智能机器人 BotID / Secret，身份按机器人来源隔离；成员搜索不代表全企业身份或业务资料权限。普通文本中的昵称、@ 字符或“我是管理员”不是身份依据。

## 授权群历史与实时群上下文

| 功能 | 飞书 | 钉钉企业机器人 | 企微智能机器人 |
| --- | --- | --- | --- |
| 私聊、群定向请求 | 已实现，受应用权限与员工使用范围约束 | 已实现私聊、群 @ | 已实现私聊、平台认证群定向消息 |
| 普通群消息 / 关键词触发 | 已实现，需普通群消息事件权限 | 当前路线不支持 | 当前路线不支持 |
| 近期群消息上下文 | 实时收到后保留有界窗口，需普通群消息权限 | 当前路线不支持 | 当前路线不支持 |
| 按授权读取群历史（离线补读） | 已实现分页读取与共享规则 | 当前机器人 Adapter 不支持 | 当前机器人 Adapter 不支持 |
| 平台原生待办、日程 | Identale 暂未接入 | Identale 暂未接入 | Identale 暂未接入 |

“离线补读”指在需要时从厂商历史接口拉取授权群的既有消息，不要求这些消息都曾在本地实时收到；它不是关掉网络后读取，也不是全群生命周期导出。飞书仍需要机器人所在群、历史/消息权限和当前调用者的授权规则。

- **实时上下文与关键词**。在飞书渠道的「群聊触发与上下文」中启用「保留近期群消息作为上下文」。飞书应用须取得 `im:message.group_msg` 普通群消息权限，并通过渠道验证。每个群或话题最多保留近期收到的 100 条消息。关闭此选项只停用这个窗口，普通群消息接收和关键词匹配仍由渠道启用状态和事件权限决定。关键词触发还要求发言者在员工使用范围内；权限不足时可保存关键词草稿。
- **授权历史与群共享**。任务可按授权从飞书分页补读历史。机器人须已加入来源群，应用须具有历史读取权限。管理员通过「群消息共享」配置同一飞书应用内的选定群互通，或将来源群定向共享给指定群或个人私聊。每一组跨群来源和目标都需要直接规则，A 可读 B、B 可读 C 不代表 A 可读 C。
- **共享规则的生效时点**。直接执行的任务在创建时固定可读来源和目标；先存为待办的任务在开始执行时固定。规则新增、修改、停用或删除，在运行侧应用后影响之后固定范围的任务，不改变已固定的群共享范围；人工继续沿用原任务范围。分页不按最新共享规则重新授予或撤销权限，但每次读取仍核验当前任务与执行身份、会话和应用绑定、原授权范围及内容来源限制；新拉取的页面仍受飞书当时的实际访问权限约束。停用规则不等于中止在途任务或收回已读内容。
- **边界和完整度**：默认查询近 24 小时，每页 1–50 条；单查询最多 10 页、500 条、64 KB，单 Run 最多 20 页、128 KB，游标有效期 15 分钟。预算耗尽返回部分/截断，`exhausted` 仅表示当前查询范围已结束。
- **不是自动搬运所有内容**：历史当前以文本投影为主，非文本会标明覆盖不完整；不自动下载历史文件、不自动展开所有话题回复，不把历史发言当新的实时任务指令。获取材料仍走单独资源授权。

钉钉 DWS 或其他厂商企业合规/存档产品与这里的机器人 Adapter 不同，不能据此把三渠道的群历史开关都标为可用。上表“暂未接入”描述 Identale，不表示厂商平台没有待办、日程或其他业务 API。Identale 自身 Task、定时触发器也不等于厂商原生待办或日历事件。

## 图片与文件的限制

- **图片/文件双向**：三家均有原生出站实现，每个文件是独立持久投递；格式/大小前检、上传、发送回执分别记录。钉钉机器人上传的图片格式与文件类型限制独立于飞书/企微，不自动转换或静默改为文本链接。
- **图片理解**：下载成功不代表模型具备视觉能力。仅在模型能力验证通过后注入获准图片；执行层通过工具读取运行层已下载的素材。

当前 Identale 出站附件采用保守上限：飞书图片 10,000,000 字节、文件 30,000,000 字节；钉钉图片/文件各 20,000,000 字节；企微图片 2,000,000 字节、文件 20,000,000 字节。企微数值是本实现上限，不是对 SDK 或整个厂商平台的全局限额声明。图片做格式及尺寸检查，支持 PNG/JPEG/GIF，飞书和企微另支持 WebP；BMP/TIFF/ICO 当前不接。钉钉机器人原生文件模板仅开放 xlsx、pdf、zip、rar、doc、docx，不支持的类型在上传前明确失败。

## 使用范围与更换机器人

飞书、企业微信和钉钉分别配置使用范围。每个数字员工按渠道分别记录首次绑定：首次接入该渠道默认**全员 + 黑名单**，黑名单为空，不受员工创建时间和其他渠道绑定情况影响；已有绑定和已保存使用范围不会自动放开。换绑或解绑后重新接入默认**空白名单**。同时开启**允许群成员在群内使用**：全员模式允许通过渠道身份校验的使用者私聊或群内使用；空白名单模式下未列入名单的人不能私聊使用，但可在机器人所在群内通过该渠道支持的 @ 或定向消息使用。黑名单始终优先，群内可用也不能绕过黑名单。

可切换为**全员 + 黑名单**。这里的全员限于当前渠道身份核验允许的使用者，不代表企业全量通讯录或已确认外部联系人归属。关闭群内可用后，群消息也按名单判断；不会改变其他渠道或网页使用权限。

新能力包默认**继承使用范围**，包括员工允许的群成员。也可对各渠道进一步限制人员，能力包不能放行员工范围已拒绝的人。

飞书的**近期群消息上下文**新建时默认打开，仍需应用取得相应消息权限。它用于保留本群的近期上下文，不是私聊使用许可。**跨群上下文共享**单独配置，决定哪些群内容可以共享到哪些会话，详见[上下文隔离](04-context-and-knowledge.md)。企微和钉钉不显示飞书专有配置。

同一机器人重新验证、重新连接或轮换密钥会保留使用范围、能力包限制、上下文、共享规则和启停状态。更换机器人需明确确认后保存：当前渠道重置为空白名单默认，旧人员名单、该渠道能力包限制、共享和缓存配置不沿用，其他渠道、网页权限和能力包资源不变。默认群内可用和能力包继承可能扩大可使用者，请在保存前检查提醒。

## 三渠道的配置及验收

### 飞书自动创建或手动关联

员工保存后，进入「设置 → 渠道 → 飞书」。未绑定时默认显示简洁的扫码创建入口，点击开始前可用右上角按钮切换手动填写已有应用的 App ID / App Secret；申请进行中、已取得凭据或结果尚不明确时，锁定自动流程，不能直接切到手动。取消已明确成功且未取得凭据，或确认已过期、拒绝、失败等终态且无未决结果后，可再切换。权限和诊断详情按需展开。钉钉和企业微信也保留已有应用的凭据关联入口。自动创建不会替换已有飞书绑定，也不会修改已有飞书应用。

自动接入使用官方 SDK 的 `registerApp`，预填该员工**已保存**的名称和职责简介。点击创建后，用飞书扫码或打开官方确认页；确认页会展示请求的应用权限。后台取得凭据后立即加密保存，浏览器不会取得 App Secret。页面关闭或暂时离开不会撤销飞书侧操作；可以回来刷新状态。明确取消只停止本地等待，不会删除已创建的飞书应用，也不会撤回已提交的飞书审批或解除外部授权。

新建申请使用 `conversation-business-v3`：一次声明基础及以下扩展权限，关闭官方 SDK 的额外预设。创建前可查看完整权限、事件清单和分组说明；当前不是按功能勾选后再申请。

**基础聊天与通讯录（必需）**保留以下 14 项应用身份（tenant）权限：

- 通讯录及租户：`tenant:tenant:readonly`、`contact:contact.base:readonly`、`contact:user.base:readonly`、`contact:user.employee:readonly`、`contact:user.department:readonly`、`contact:department.base:readonly`、`contact:department.organize:readonly`、`contact:user.employee_id:readonly`。
- 消息与群：`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:message:send_as_bot`、`im:message:readonly`、`im:message.group_msg`、`im:chat:readonly`。普通群消息权限用于现有群上下文及原消息读取，不等于允许未 @ 消息自动执行任务。
- 事件：`im.message.receive_v1`、`im.chat.member.bot.added_v1`、`im.chat.member.bot.deleted_v1`、`im.chat.disbanded_v1`。

**扩展权限独立显示，不作为基础渠道启用条件**。每组及每项权限分别显示「授权已生效」（granted）、「授权未齐」（missing）或「授权待确认」（unknown）。未返回或无法核验的权限不会算作已授权；飞书可能忽略未识别的申请项，应以实际权限清单为准。

- **消息、附件与群**：申请附件、群信息/成员、公告、Pin、表情及包含其他机器人消息的权限。附件收发已有实现，其余工具未全部接入；其他机器人消息仍不会作为用户任务。
- **组织、部门与成员关系**：申请 Contact 基础资料和 Directory 部门、员工、路径、上级等字段权限。当前通讯录仍使用 Contact v3，Directory 搜索与新接口尚未接入，也不保证全公司资料可见。
- **文档与评论读写**：指定 Docx 正文读取已实现；创建、修改及评论读写/删除权限预先申请，相关写入工具待接入，仍需具体文档的访问或编辑权。
- **多维表格读写**：预申请应用、表、字段、记录和视图权限，包括表、字段和记录删除；业务工具待接入。记录查询申请的是 v1 records/search 的 `base:record:retrieve`，不代表 v3 read；仍受表格及行列访问范围限制。
- **日程读写与邀请**：预申请日历、日程、忙闲、取消日程与回复邀请权限，业务工具待接入。应用需要相应日历访问权，个人身份操作仍需另行完成个人 OAuth。
- **待办、清单与评论读写**：`task:task:write`、`task:tasklist:write`、`task:comment:write` 是包括读取、创建、修改和删除的宽权限；业务工具待接入，不代表可以访问任意个人任务。
- **会议纪要与妙记读取**：指定会议及妙记资料读取已接入，搜索工具待接入。应用身份的会议录制权限可能涉及企业范围，仍核验具体资料可见性和产物状态。`vc:meeting.search:read`、`minutes:minutes.search:read` 尚未在真实租户控制台验证可申请状态；`vc:note:read`、`minutes:minutes.artifacts:read` 的独立官方接口文档证据尚未补齐。这四项目前依据官方 CLI 声明，页面逐项提示，不能视为已核准。
- **审批读写（高影响）**：预申请 `approval:approval.list:readonly`、`approval:instance`、`approval:task`、`approval:instance.comment`。传统审批应用权限可能覆盖整个企业审批数据，且包含同意、拒绝等审批决定。业务工具尚未实现；实际操作仍需核验具体审批单、操作者和动作授权。

应用权限获批不等于具体资料 ACL、个人 OAuth 或实际业务操作获准，也不代表相关工具已经实现。当前 v3 清单均为 tenant 权限，不申请个人身份权限；除下述新应用通讯录范围配置外，不调用其他应用管理写入或发布接口。已接入资料读取的范围见[读取会议资料与云文档](27-business-resource-reads.md)。

每次创建保存当时申请清单的快照，后续展示和检查沿用该清单，不随新建默认值变化。旧记录没有快照时，严格按原 `conversation-directory-v1` 的 14 项权限及四项事件处理，不追加入后续版本的扩展或范围管理权限。

**新应用的全员通讯录范围**：v3 额外申请 `application:application.contacts_range:write`，独立显示为「通讯录范围管理（全员）」。仅通过本次自动创建流程产生的新应用，在实际权限清单确认这项应用身份权限获批后，自动调用 v6 通讯录范围配置接口，提交 `contacts_range_type: all`。飞书更新线上范围后立即生效，不需要此接口再发布版本。该管理权限本身可能允许管理企业内其他应用，但 Identale 固定只操作本次新建 App ID，不接受浏览器传入目标应用或范围。它不改变机器人的可用范围、Identale 员工使用名单或具体资源 ACL。

历史 v1/v2 注册记录和手动填写接入的应用不会补申请这项权限或执行范围修改。权限尚未获批时保留等待状态；已连接的新应用也可随本页复查在获批后完成范围设置，不重新绑定连接。页面把权限是否获批与范围设置结果分开显示；范围设置失败不会关闭已通过基础检查的渠道。明确的权限拒绝可在后续复查时重试；超时、断连、异常响应或写入期间重启造成结果不明时停止重复写入，需到飞书后台核对。已成功设置后不会持续维持全员状态，也不会覆盖管理员后续主动缩小范围。

如果凭据已返回后改由手动流程保存同一个应用，或崩溃恢复时无法证明当前连接由自动流程完成，则跳过尚未执行的范围修改，避免误改手动连接。

取得凭据后，系统检查基础权限、机器人身份、通讯录可见范围、部门读取与真实姓名样本。基础缺项、范围为空或结果无法核实时，保留加密凭据并阻止渠道启用。扩展权限未获批或无法确认不会单独阻断基础启用；但若飞书尚未发放凭据，仍须先完成飞书侧创建流程。基础检查通过后保存正式渠道，再独立查看长连接、入站消息与使用范围。

**自动复查与恢复**：凭据已保存后，停留在可见、活动的当前接入页面时会自动复查，未通过时逐步退避，检查间隔为 5、10、20、30 秒，之后最长 60 秒；网络失败另有退避。也可点击「重新检查已保存的应用」，无需重新创建。离开此页、切换员工或导航、隐藏浏览器标签页时停止后续轮询，有未保存修改或其他操作时暂停自动检查；已经提交的服务端检查不会因离开页面撤销。重新打开或回到可见页面先读取状态，再决定是否继续复查，不会自动创建另一项应用。认证失败、授权撤销或绑定变化等情况会停止自动复查，需要先处理问题。

基础渠道启用后，复查刷新本次申请的权限清单状态，并仅为尚未完成范围设置的 v3 新建应用执行上述操作；不重新保存或替换已有渠道，不把旧的机器人身份、通讯录检查时间当成新验证，也不会因扩展缺项关闭基础渠道。全部申请权限确认生效、且没有待执行的范围设置后停止自动复查；这不是长期后台权限监控。

扫码卡片带飞书标识并注明「identale 发起」，不是飞书官方页面。确认链接仅允许指定飞书官方 HTTPS 域名；链接较长时增大二维码，过长或生成失败时保留完整官方确认链接供点击，不截断员工资料或使用第三方短链接。过期链接不继续提供扫码确认。

**审批和连接边界**：租户免审规则、开发者身份、可用范围和发布流程决定是否需要管理员审批，不应把此流程称为“全部免审批”。SDK 返回凭据不证明发布、审批、事件订阅方式或长连接已经完成；本流程不代替管理员审批。请按页面检查结果，在飞书后台补齐通讯录可见范围、所需发布或审批及长连接事件配置。扫描被取消、过期或中断后，如果飞书可能已确认创建，应先检查飞书后台，避免重复创建。取消等待成功只结束本地流程；切换到手动接入也不代表飞书审批已撤回或外部应用已删除。创建请求结果不明确时继续锁定，先刷新或重试同一次创建请求。当前仅支持飞书国内版，不接续 Lark 国际版注册。

**验证范围**：历史 v2 及本轮 v3 的隔离数据库、合成 HTTP、页面组件、类型与构建验证分别见当日变更记录，不把旧验证结论作为新逻辑的验收。尚未使用真实飞书租户验收，不能将本地测试视为真实审批、权限申请或消息收发通过。依据：[飞书官方扫码创建文档](https://open.feishu.cn/document/mcp_open_tools/integrating-agents-with-feishu/scan-to-create-an-app-in-one-click-nodejs)、[官方 Node SDK](https://github.com/larksuite/node-sdk/blob/main/README.zh.md#一键创建应用)、[v6 更新应用通讯录权限范围](https://open.feishu.cn/api-explorer?from=op_doc_tab&apiName=patch&project=application&resource=application.contacts_range&version=v6)。

### 飞书应用机器人

1. 配置飞书应用的 App ID / App Secret，启用机器人和所需消息权限。应用 App ID 与机器人在消息中的身份不是同一个标识；系统会自动查询机器人身份，无需手工填写机器人 ID。
2. 保存时如果应用接口已完整确认机器人和租户，页面显示身份已验证，可按使用范围使用。如果仅缺消息侧租户信息，页面显示等待首条消息；连接在线后发送普通私聊，或在群内真实 @ 机器人，即可自动确认，不需要验证口令或人工候选确认。
3. 第一条消息仍按已保存的使用范围和黑名单判断，发信者不会因完成身份确认而自动获得使用权。普通未 @ 群消息、其他机器人和系统事件不能完成确认。
4. 身份冲突或无法查询可信机器人身份时保持阻断，请检查应用配置并重新验证；不会把任意群成员的身份当成机器人，也不会静默更换已有绑定。

### 钉钉企业内部应用

#### 扫码创建与手动关联

员工创建后，在「渠道连接 → 钉钉」默认显示扫码创建入口；右上角「绑定已有应用」可切换为 Client ID / Client Secret 填写。申请进行中或结果尚未确定时不能直接切换。页面可复制数字员工名称，当前不自动设置或修改钉钉机器人名称。飞书、钉钉和企业微信的手动关联入口均保留。

扫码使用钉钉官方 OpenClaw 连接器的注册协议，但不安装 OpenClaw 或 DWS，也不托管 DWS 用户 OAuth。默认使用 Identale 自有来源标识 `identale`，直接向钉钉申请注册；部署方可通过 `DENTITY_DINGTALK_REGISTRATION_SOURCE` 配置自有来源，不能借用其他产品标识。无需先配置来源才能点击创建，是否接受本次注册以钉钉接口返回为准。手动关联已有应用仍保留。

1. 点击一次「扫码创建新机器人」，恢复仍有效的申请或创建新申请后直接显示二维码，无需再点开始。用钉钉手机 App 扫描二维码，或打开官方验证页。页面显示剩余秒数；过期撤下二维码并提示，不自动创建新的机器人。二维码在本地生成，不发送给第三方图片服务。请核对官方页面的企业、机器人创建内容和授权范围后再确认。
2. 完成官方操作后，Identale 取得机器人应用凭据，新连接自动验证并加密保存到当前员工，应用 Secret 不返回浏览器。保存失败可点击「重新检查并保存连接」，在原会话有效期内恢复，不必重新创建机器人。已有应用不同于新应用时必须再次确认换绑及当前渠道使用范围重置。
3. 注册会话仅当前管理员、工作区和员工可用，最多保留 10 分钟。切换页面、员工或渠道、刷新或关闭浏览器只停止页面轮询，不取消申请；在有效期内返回同一员工页面，会读取原申请状态并继续等待，取得凭据后自动保存新连接，不重复创建。离开期间不延长二维码有效期。显式关闭扫码、取消、过期和控制平台重启会使该流程失效；短时间内返回也会显示原申请失败或过期的提示。取消只停止 Identale 本地流程，不撤销已经在钉钉创建的应用；中断或结果不明时先去官方后台核对，必要时手动关联，避免重复创建。临时申请不持久化，不保证跨服务重启恢复。
4. 注册期间每位管理员每分钟最多发起 5 次，单个员工同一管理员只能保留一个进行中的会话。轮询按钉钉给定间隔执行；网络超时、限流或服务暂时异常时暂停，可在原会话有效期内重新检查，不重复创建。钉钉暂时返回失败、过期或未知状态时，在原申请有效期内最多继续检查 2 分钟，不重复创建；持续异常后终止。明确接口拒绝、无效响应结构或成功但缺少凭据仍立即终止。临时会话容量有限，繁忙时稍后重试或使用手动入口。
5. 扫码成功只表示取得应用凭据，不等于企业目录、Stream、首条消息身份或使用范围已全部通过。保存后继续按下方流程核对。此入口不授予用户身份的文档、待办、日历或其他 DWS 权限。

该协议实现以[官方注册代码](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector/blob/main/src/device-auth.ts)和[官方来源配置](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector/blob/main/src/device-auth-config.ts)为依据。注册初始化接口已实测：不传来源、空来源及 `identale` 来源均获成功响应；这仅代表初始化可用，完整扫码创建及租户验收仍需实际验证。

#### 应用配置与接入验收

1. 创建企业内部应用，启用应用内机器人，使用 Client ID / Client Secret；消息接收采用 Stream。群自定义 Webhook 不是这条连接。
2. 配置机器人发送权限 `qyapi_robot_sendmsg`。通讯录基础读取参考 `qyapi_get_department_list`、`qyapi_get_department_member`、`qyapi_get_member`，同时限定部门/人员可见范围并核对必要上级部门。以当前控制台和实际接口验证为准，不额外强制手机号、邮箱或流式卡片权限。
3. 完成企业要求的审批和版本发布，将机器人加入明确的测试群。Stream 负责接收，回复走机器人 OpenAPI，不向 Stream 写回消息，也不依赖会过期的 SessionWebhook 完成长任务通知。
4. 保存 Client ID 和 Client Secret 后，分别查看长连接、首条消息和通讯录状态。连接在线后发一条普通私聊或群 @ 消息。第一条通过校验的消息自动确认机器人和企业来源，随后按员工使用范围处理同一条消息。目录权限不足时仍可保存凭据，私聊使用权需另行配置。
5. 应用凭据的 Client ID、机器人 robotCode、企业 corpId 分别校验，不要求 robotCode 与 Client ID 相等。回调中的 chatbotUserId 可能因私聊或不同群而变化，不作为跨会话机器人身份或人员身份。群上下文按原群分开，同群成员共享本群交互；不同成员的私聊保持隔离。
6. 钉钉当前不支持引用指定消息，但可以在原群或原机器人私聊发送新消息。身份或权限错误只发送固定提示，不执行用户任务；前提是原目标可安全确认且机器人具备发送权限。目标不明、连接身份冲突、机器人已无法发送或结果不确定时，不猜目标、不改投其他会话，也不自动重发未知结果。

升级前若保存过会话内机器人账号作为全局身份，渠道会提示需要重新验证，不会自动清理会话、消息或改绑。管理员应先核对在途任务及投递，再重新验证当前应用；已有旧会话是否接续不是本次修复的保证。

### 钉钉通讯录授权与同步

保存机器人连接后，可在「通讯录设置」打开[钉钉开发者后台](https://open-dev.dingtalk.com/)。先开通部门、部门成员及成员信息读取 API 权限，再设置应用可访问的部门与人员范围，按后台要求确认生效。两者不是同一配置，取得机器人凭据不代表已具备全企业通讯录权限。

返回页面点击「检查并同步通讯录」，查看进度、最近成功时间与结果。厂商明确返回缺失权限时展示权限标识；其他接口或网络失败保留其错误分类，不笼统显示“缺权限”。页面不会自动申请权限或替管理员审批。

### 人员选择与通讯录同步

飞书、钉钉在使用范围、能力包范围和人工确认人选择处共用本地通讯录快照；飞书群共享指定人员也使用同一快照。打开选择器先展示已同步的人员，可搜索姓名、浏览部门和分页加载；不会在每次选择或每条消息到达时重复请求厂商通讯录。

- 快照按应用实际获准的范围递归读取部门并分页读取人员。全企业授权下可获取全部接口可见的人员，不会自动扩大已有应用的权限。
- 页面可点击「同步通讯录」，并查看正在同步、进度及最近结果。后台同步与手动同步复用同一任务；同步成功后列表更新，已有选择不因刷新丢失。
- 暂时网络失败保留上一份完整快照并显示失败；明确的权限撤销、范围收窄或换绑使旧快照失效。初次同步完成前列表可能为空。
- 消息鉴权、能力包筛选及人工确认收件人判断使用本地配置、快照或已绑定关系。新人员、离职或部门变化需要同步后生效；快照不是厂商权限变更的实时订阅。
- 飞书、钉钉全员加空黑名单不要求先同步通讯录；明确人员名单按同应用、同类型 ID 比较。部门名单按最近成功且仍有效的完整快照判断：该快照中不存在的人不命中部门白名单，也不命中部门黑名单；因此新入职或转部门但尚未同步的变化要等下次同步才能反映。快照缺失、失效或部门信息未知时，部门白名单不提供授权，部门黑名单保守阻断。企微仍使用原有绑定规则。
- 同步有安全预算，达到预算会报告失败，不把截断列表当作完整通讯录。只有全部分页成功才发布新快照。

企业微信不支持这条全量部门快照路线。人员选择先显示已选或已绑定人员，每次输入关键词搜索都会调用官方成员搜索，并保留已有身份绑定；不可把搜索结果当作企业完整通讯录。身份绑定独立持久保存，不会随临时候选缓存淘汰，鉴权和私聊发送收件人判断不依赖实时搜索。

### 企业微信智能机器人与成员搜索

**新建机器人：默认扫码创建**

在员工的企业微信渠道页点击「扫码创建机器人」，进入企业微信官方窗口操作。Identale 使用自己的来源标识 `identale`，不借用其他产品标识。未绑定时默认显示扫码创建，右上角「绑定已有应用」可切换为凭据填写。收到可信的 BotID / Secret 回调后自动保存并启动连接；保存失败可重试保存，无需再创建机器人。若当前已连接其他机器人，仍须明确确认换绑及当前渠道配置重置。扫码不代表已获得通讯录、文档等业务权限，也不代表长连接或消息收发已验证。

- 页面显示数字员工名称并可复制到企微使用；目前不自动设置或修改企微机器人名称。已有机器人继续手动填写 BotID / Secret，不通过扫码自动选择或关联。飞书、钉钉也保留原有手动凭据入口。
- 有未保存修改时先保存或清空凭据并取消其他修改，再开始扫码。等待期间可取消，取消后可切换已有应用填写；弹窗被拦截时允许本站弹窗后再试。
- 单次最多等待 5 分钟。关闭、取消、离开页面或超时后不再接收该次结果；不会自动重试或删除已在企微创建的机器人。如果已创建但回填失败，请到企微后台取得凭据并手动填写。
- 扫码创建和凭据回传已有实际应用验证。本次自动保存、失败重试与入口切换通过本地合成测试，更新后的完整真实扫码流程仍需验收。

流程参考企业微信[浏览器 SDK](https://www.npmjs.com/package/@wecom/wecom-aibot-sdk)与腾讯云[公开接入示例](https://github.com/TencentCloudADP/adp-chat-client/blob/main/client/packages/adp-chat-component/src/components/Channel/WecomBotConfigDialog.vue)。

**手动配置、连接验证与成员搜索**

1. 只需智能机器人 API 长连接的 BotID / Secret，不再配置传统自建应用、CorpID、AgentId、目录 Secret、可信 IP 或同企业声明。机器人只维持一条接收/发送连接，不与 URL 回调同时使用。
2. 创建向导检查输入后允许继续。保存完成才由官方长连接认证凭据，页面分别显示认证、连接和首条消息状态。连接在线后发送普通私聊或群定向消息，首条通过校验的真实消息自动确认机器人来源，并在同一次处理中继续鉴权；不使用验证口令或人工候选确认。
3. 使用范围与其他两种渠道一致，新建数字员工首次接入默认全员加空黑名单，并允许群成员在群内使用；换绑重置为空白名单。可配置人员名单或切换全员加黑名单，不要求先搜索某个人才能使用全员模式。
4. 成员可按姓名、拼音、英文名或别名实时搜索。部门路径仅用于区分同名，不提供按部门授权。搜索结果不写入临时人员池；选择人员时才保存必要资料，不设 500 人上限。搜索结果长时间未选择时需重新搜索，已选择或已绑定人员不因搜索过期丢失。接口不可用会明确提示，不以旧搜索结果伪装成功。保存资料不授予身份或使用权，来源和凭据变化后不沿用。
5. 搜索选人后可立即保存使用范围、能力包范围或人工确认人，未完成身份关联时显示“待验证”，不要求管理员留在页面等待。页面提供 **6 位数字验证码**，保留前导零，24 小时内一次有效。管理员必须只把码交给选中的那位成员，请其向当前机器人私聊发送；机器人不主动发送验证码，不要求已有近期私聊会话。
6. 只检查纯文本私聊里恰好一个独立的 6 位数字：先匹配当前待验证且未过期的码，再匹配 3 天内已使用、已过期或已作废的旧码。命中当前码后，先核验身份，再判断使用权限，因此白名单尚未绑定的成员也能回码。可附带文字，但不能从更长数字中截取。未命中、包含多个 6 位数字、只有“验证码”字样，以及群聊、引用、混合消息，均按普通消息进入原有权限校验，不能据此绑定。命中的私聊核验消息不进入模型、业务任务或正文诊断；成功固定回复“身份验证成功”，旧码按已使用、已过期或已作废提示，不回显码或人员信息。分体持久结果尚未确认时仅提示正在同步，不冒称成功。
7. 绑定证据是**管理员转交确认**：系统证明回码账号持有这枚码，不能独立证明管理员确实把码交给了所选人员。不得按同名自动绑定。成功后，同一机器人连接的使用范围、能力包与确认人共用这条映射，页面自动更新，不需再次保存；不跨机器人或来源共享。同一机器人重验或仅更换 Secret 保留已验证人员和配置；新凭据身份重新确认前暂停使用，确认一致后恢复。换绑其他机器人需重新关联，待验证验证码不沿用。重验期间暂停消息处理；若待发送通知已耗尽重试，身份恢复不会自动重发。
8. 身份绑定不授予使用权。员工设为全员可用且没有无法判断的黑名单时，未绑定账号仍可正常聊天；员工与能力包的白名单按成员匹配：A 已绑定并命中时可以使用，新增待验证的 B 不会阻断 A；B 和未列入的 C 不获得使用权。未绑定黑名单仍保持保守阻断。未绑定确认人仅保存目录引用，不会把搜索 ID 当收件 ID。人工确认按问题路由独立处理：选中已绑定的 A 时，检查 A 的当前权限后发送，不等待另一规则中的 B；选中未绑定的 B 时，只有该请求等待 B 验证。绑定后对尚未投递的确认重新核对当前使用权再投递，不自动重发已失败或结果未知的消息。
9. 页面重开会恢复仍有效的同一码。到期后，在页面可见时自动获取新码；隐藏或关闭页面不持续轮换。显式重新生成会令该成员旧码失效。并发请求复用同一有效码。同一数字员工、同一渠道的有效码和保留期旧码不重复，不再设置 10 人待验证或 100 条旧码的固定上限。不同数字员工可以使用相同数字，必须向页面指定的机器人发送，避免误投。六位数字空间有限，无法生成可用码时会明确提示失败，不覆盖仍有效的码。
10. 旧码仅在首次失效后的 3 天内参与识别：提前使用或作废从完成时刻计算，自然过期从原有效期结束计算。到期后不再作为验证码识别，后台按批次清理过期状态和码材料。历史只在同一连接、来源和凭据版本内使用，换绑或更换凭据后不沿用；有效码与仍保留的旧码不会重号。普通业务数字若恰好命中这段历史，也会收到旧码提示。
11. 验证没有失败次数、冷却或冻结限制，也没有解冻入口；六位数字可能被猜中，管理员应仅把验证码交给选定成员。平台加密保存当前明码，运行配置仅含带密钥的摘要；管理接口禁止缓存，码不写入 URL。


### 本地验证与真实验收

- 飞书、钉钉通讯录首次验证从已授权部门继续寻找真实姓名样本，包含后代和分页；最多执行 32 次分页 Port 读取并发现 1000 个部门。各 Adapter 内部请求也保留自身上限。这是有界采样，不是全量同步；预算耗尽报告 `limit`，只有已探索范围穷尽才报告 `no_sample`。
- 企微人工确认通知只发给已经授权的固定私聊接收人，发送失败不会自动改换接收人或重新执行业务任务。
- 本地 fixture 验证不触达真实租户。真实验收需另行明确测试企业、机器人、人员、测试群和消息内容，依次验证目录读取、私聊一收一回、群 @ / 定向消息一收一回、未 @ 不触发、重复消息不重复执行、重连、范围变化撤权。
- 图片/文件入站支持不等于所有类型/会话均支持，也不等于已取得视觉模型能力。钉钉群文件接收、各家文件类型/限额分别验收；模型输出的路径、URL 或 media_id 不能直接变成获准附件。

## 接收、历史与发送事实

入站校验后才生成可信 `ChannelMessageEvent`，保留 event ID、连接、租户、来源和消息范围。历史消息的 `origin` 与实时事件不同；历史补读不能伪装成新的实时指令。

历史页必须说明分页游标、是否耗尽以及 `coverage`。`exhausted` 只针对该查询 / 身份，不表示获得了整个会话生命周期的全部消息。群列表中的话题根消息也不代表已展开全部回复。

出站目标必须已获授权，模型不能自行选择接收人。发送状态区分厂商接受、厂商确认发送成功和结果不确定；确认发送成功不代表用户已读。企微成功发送回执会显示发送成功，超时或断线导致的未知结果不自动重试。附件按独立操作处理，以便部分成功后只核对未确定项，不重发整批。通知失败不重跑业务任务。

钉钉主动私聊和群消息收到 `processQueryKey` 后会先保存受理凭据，再有限查询发送结果。每条消息最多查询 5 次：首次等待 2 秒，后续每次分别等待 5、10、20、30 秒；网络耗时另计，限流时遵守更长的 Retry-After，但从保存受理凭据起最多保留 5 分钟查询窗口。查询次数、下次时间和在途状态持久保存，服务重启后只继续剩余查询，不重新发送消息。

- `SUCCESS` 才更新为发送成功，不推断用户已读；`PROCESSING` 继续有限查询；`RECALLED` 记录为失败并注明已撤回。
- 查询超时、接口结果不完整或未知状态在预算内继续查询；预算耗尽、权限不足或绑定变化后保留未知，不自动重发或改换目标。
- 只处理启用此功能后获得受理凭据的投递，历史未知记录不批量补查。发送请求没有取得可信 `processQueryKey` 时无法自动查询；收到凭据前发生进程崩溃也无法保证恢复它。
- 私聊每次只投递给一个已授权人员。无效收件人明确失败；厂商明确列出该收件人被限流时沿用既有有限安全重试。错误列表不完整、格式异常或包含其他人员时视为未知，不把它当成可以重发的证据。

接口合同参考：[官方 SDK 机器人 API](https://pkg.go.dev/github.com/alibabacloud-go/dingtalk@v1.7.46/robot_1_0)。本轮有限查询逻辑已用隔离 HTTP、运行时和 SQLite fixture 验证；该验证不替代新增查询逻辑在真实企业环境的验收，也不改变已有真实发送测试记录。


## 新增或修改渠道

会话、会议资料和 Webhook 分别通过 [Channel Port](../../packages/application/src/channels/ports.ts)声明。`supported` 表示实现范围，`availability` 表示当前可用性，可取 `available`、`authorization_required`、`unsupported` 或 `unknown`。

1. 先列实际场景及厂商能力 / 权限资料，明确机器人、委托用户、目录应用与会议资料各自身份。
2. 实现所需 Port；不支持的能力明确返回，不用空列表假装成功。SDK 放在 Adapter，不流入领域 / 应用代码。
3. 经可信 Adapter 建立连接、应用、租户、用户与群 / 话题范围。不要从模型参数或显示名推断身份。
4. 评审游标、分页覆盖、重连、重复 / 乱序事件、凭据轮换、撤权、限流、部分发送与未知结果。
5. 先用合成输入验证契约，再单独确认真实测试账号、权限、数据和消息目标。真实测试结果按场景报告，不复用私有脚本中的账号或数据库。
